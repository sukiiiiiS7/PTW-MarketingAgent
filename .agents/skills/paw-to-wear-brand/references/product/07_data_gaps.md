# Product Knowledge Gaps

These are known gaps that should block unsupported claims rather than invite inference.

| Priority | Issue | Evidence | Risk to Agent | Recommended Fix |
| --- | --- | --- | --- | --- |
| P0 | Urban exists in live Shopify catalog but is missing from the Pattern master. | Live export includes Urban Hoodie / Sweatshirt / T-Shirt; Pattern sheet has no Urban row. | Agent cannot reliably know canonical Urban customization, intent, code, pet support, or story rules. | Add a complete Urban row to Pattern master and assign a Pattern Code. |
| P1 | Together and Wander exist in Pattern master but have no live products in current Shopify export. | Pattern master contains Together (008) and Wander (009); no active products with those style names. | Agent may market unavailable designs. | Add an availability/status field to Pattern truth: draft / active / paused / retired. |
| P0 | Garment taxonomy omits a current Baseball Cap product. | Shopify export contains 'Custom Pet Embroidered Icon Stitch Baseball Cap'; style_name is blank. | Catalog routing and generated copy may misclassify or omit it. | Either add Baseball Cap under Garment > Hats or retire/merge it; set style_name=Icon if appropriate. |
| P1 | Beanie and Scarf lack canonical construction, dimensions/fit, and care facts in supplied structured data. | Export only provides material and color variants; generic body copy is not reliable enough for structural facts. | Agent may invent specs or repeat unsuitable templated copy. | Create accessory spec fields: dimensions, knit/weave construction, fit, weight, care, country of origin if relevant. |
| P1 | T-Shirt construction and fit are under-specified. | Structured source provides 100% cotton / 240g jersey and sizes, but no canonical cut/fit/construction details. | Marketing may overstate fit or garment quality. | Add fit and construction fields to garment truth. |
| P0 | Happiness Guarantee is not fully aligned with the formal return/refund policy. | Product FAQ promises free remake for a pet-portrait issue; formal policy defines damaged/defective/incorrect-item remedies but not portrait-likeness criteria. | Support/marketing agent may promise a remedy beyond ops policy. | Define 'portrait issue', proof required, eligibility window, and whether remake is the exclusive/default remedy; then mirror it in formal policy. |
| P0 | Offer content is time-sensitive and currently appears stale. | Product pages still mention an August promotion on 2026-09-04. | Agent may publish expired discounts. | Move offers to a dated campaign truth source and require active-date validation. |
| P1 | Customization option prices are not fully captured in Pattern master or Shopify export. | Pattern master lists option names, while live UI can contain surcharges (e.g. size/sleeve add-ons) that are not represented in the export. | Agent may quote incorrect upgrade pricing. | Create a separate customization_pricing table keyed by pattern + garment + option + value + effective date. |
| P1 | Color availability is not purely garment-level. | Urban / Devotion / Halo have different color sets from the common Hoodie/Sweatshirt palette. | A generic color list can produce unavailable combinations. | Store colors at SKU/product-handle level; garment truth should only describe common palette, not availability. |
| P2 | Exact size-chart measurements are not in the supplied product export. | Only variant labels are present. | Agent cannot answer measurement-level sizing questions safely. | Add size chart measurements by garment and size. |
